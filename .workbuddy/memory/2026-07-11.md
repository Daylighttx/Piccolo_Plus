# 2026-07-11 — Piccolo_Plus clone + build

## Goal
Clone https://github.com/Daylighttx/Piccolo_Plus (fork of BoomingTech/Piccolo, a C++/Vulkan mini game engine for GAMES104) and compile+run it.

## Network constraint discovered (IMPORTANT)
This sandbox has a very flaky GitHub connection:
- git smart-HTTP `clone`/`fetch` often fails to connect (timeout) or drops mid-transfer.
- codeload.github.com tarball redirects and **ignores HTTP Range requests** (returns 200 + full stream from byte 0), and the connection drops at ~64 MiB per transfer. So a full tarball download is impossible here.
- A single git blob fetch fails ~half the time ("curl 56 Recv failure: Connection was reset") but succeeds on retry; successfully-fetched objects are cached.

## Working approach (partial clone + sparse checkout)
1. `git clone --depth 1 --filter=blob:none --no-checkout <url> .` → fetches only commits+trees (tiny, succeeds).
2. `git sparse-checkout init --no-cone` then `git sparse-checkout set '/*' '!engine/asset/level/' '!engine/asset/objects/' '!engine/asset/texture/' '!engine/asset/world/'` to EXCLUDE the large runtime binary assets (not needed to compile).
3. Populate working tree per-directory with `git checkout HEAD -- <dir>` wrapped in a retry loop (up to ~60 tries each). Each target needs ONE clean connection; cached blobs persist across retries. Background script at /tmp/co_pp.sh writes progress to checkout.log.
4. engine/3rdparty vendors VulkanSDK + glfw + JoltPhysics etc. — no system Vulkan SDK needed (engine/CMakeLists.txt points to engine/3rdparty/VulkanSDK).

## Toolchain
- VS2022 Community, MSVC 14.42 (cl.exe x64) — verified works.
- CMake 3.30.2.
- No Ninja → use CMake "Visual Studio 17 2022" generator (MSBuild).
- Build: `cmake -S . -B build` then `cmake --build build --config Release` (per build_windows.bat). Output: bin/PiccoloEditor.exe.
- NOTE: headless sandbox has no GPU/display → GUI Vulkan editor likely can't actually render; "run" may only verify the exe launches / init.

## Session 2 (15:10) — resume checkout
- The original background co_pp.sh from session 1 was STILL running across sessions, spawning many git.exe and holding .git/index.lock (caused "Unable to create index.lock: File exists"). Had to kill it: `taskkill /F /IM git.exe` needs MSYS_NO_PATHCONV=1 in git bash; better to use PowerShell Get-CimInstance Win32_Process to find bash.exe running co_pp.sh and Stop-Process. cmd /c is BLOCKED by security policy.
- KEY: VulkanSDK/bin/{Linux,MacOS} = 61 MB of Linux/Mac binaries (glslangValidator, libMoltenVK, validation layers) — NOT needed on Windows. This 61MB single dir was the reason `git checkout HEAD -- .` catch-all always failed (exceeds ~64MiB per-connection cap). Windows only needs VulkanSDK/bin/Win32/glslangValidator.exe (7.5MB) for shader compile.
- Updated sparse to also exclude '!engine/3rdparty/VulkanSDK/bin/Linux/' '!engine/3rdparty/VulkanSDK/bin/MacOS/' '!engine/3rdparty/JoltPhysics/Assets/' '!engine/3rdparty/JoltPhysics/Docs/'.
- WORKING METHOD to populate: `git diff --name-only --diff-filter=D HEAD > missing.txt` then batch checkout 40-100 files/batch with retries → small fetches that reliably succeed (~1-12 tries/batch). Do NOT use `git cat-file -s` on missing blobs (it triggers a fetch). CAUTION: `git checkout HEAD -- <explicit path>` IGNORES sparse rules, so missing.txt must be FILTERED to drop sparse-excluded heavy files (VulkanSDK/bin/{Linux,MacOS}, VkLayer_khronos_validation.dll 27MB, sol2-3.3.0/documentation, JoltPhysics/{WebIncludes,Docs,Assets}) — otherwise a batch stalls forever fetching a 43MB blob. Get blob sizes safely via `git ls-tree -r -l HEAD` (no fetch).
